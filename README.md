## Overview

Negative reviews on e-commerce platforms pile up faster than any support team can read them, and buried inside that pile are the complaints that genuinely need a human — a defective product, a suspected counterfeit, or a refund that never arrived. This project builds an **end-to-end complaint intelligence pipeline** over the Electronics slice of the McAuley-Lab **Amazon Reviews 2023** dataset and converts 60,000 one- and two-star reviews into a ranked, explainable work queue.

The pipeline composes **six independent analytical modules** and fuses their outputs through a **transparent additive score**, so that every triage decision can be decomposed signal-by-signal and defended in front of a human reviewer. Unlike black-box neural ranking systems, every point in the final score maps to a checkable, named signal.

### Why this matters for a Recommender System course

Although the project title references "recommendation," the actual contribution is on the **reliability side of recommendation**: a recommender that surfaces unreliable products undermines user trust. This pipeline identifies the complaint signals that should *down-rank* or *flag* products, providing the safety layer that any production recommender system requires.

## Problem Statement

Given the volume and imbalance of negative product reviews on modern e-commerce platforms, how can we automatically:

1. **Categorize** complaints into actionable themes (refund, quality, performance, delivery, seller, appearance)?
2. **Quantify** the emotional severity of each complaint?
3. **Discover** complaint topics that the dictionary did not anticipate?
4. **Detect** anomalous reviewer behaviour that warrants scrutiny?
5. **Classify** complaint themes with a supervised model?
6. **Fuse** all of the above into a single, transparent triage score?

This project answers each question with a dedicated module and combines the outputs into a single defensible queue.

## Methodology

### Module 1 — Dictionary-Based Complaint Categorization

Six expert-defined themes are matched against the lower-cased review text:

| Theme          | Example keywords                                   |
|----------------|----------------------------------------------------|
| `quality`      | broken, defective, damaged, stopped working, faulty|
| `delivery`     | late, not delivered, missing package, shipping      |
| `seller`       | scam, fake, counterfeit, wrong item, fraud          |
| `refund`       | refund, return, replacement, money back             |
| `performance`  | slow, overheating, battery, crash, lag              |
| `appearance`   | scratched, stain, smell, looks used, not as described |

Each review receives a multi-label vector, a count of matched themes, and a primary label. Reviews that match nothing are **not discarded** — they are routed to the unsupervised modules, which can surface complaint shapes the dictionary missed.

### Module 2 — VADER Sentiment Severity

VADER compound score (range −1 to +1) is computed over the merged title + body, capped at 3,000 characters. The **complaint severity** is the negated compound:

```
severity = -compound
```

so that larger values mean more severe. The join is idempotent — rerunning the cell replaces the sentiment columns rather than duplicating them.

### Module 3 — LDA + NMF Topic Models

Both topic models run over a reproducible 8,000-review sample:

- **LDA:** count matrix, English stop words, 8,000 features, 1–2 grams, min document frequency = 5, 8 topics, batch learning, 10 iterations.
- **NMF:** TF-IDF matrix, NNDSVDa initialization, 300 iterations, 8 topics.

Themes that surface in **both** models are treated as trustworthy; topics unique to one model are treated as candidates.

### Module 4 — Sentence Embeddings + KMeans

- Sample: 5,000 reviews (from the topic-model sample)
- Embedding model: `all-MiniLM-L6-v2` (384 dimensions, 128-token truncation)
- Clustering: KMeans with `k = 6`, 10 initializations, `RANDOM_STATE = 42`
- Quality metric: silhouette score on a 2,000-point subsample
- Sweep: `k ∈ {4, 6, 8, 10, 12}` to verify that 6 is not arbitrary

A TF-IDF + truncated SVD fallback (128 dimensions) is included if the transformer cannot be downloaded.

### Module 5 — IsolationForest Anomaly Detection

Ten standardized reviewer-level features:

1. Review count
2. Mean rating
3. Negative ratio
4. One-star ratio
5. Complaint ratio
6. Image ratio
7. Distinct product count
8. Mean text length
9. Total helpful votes
10. Network degree

Configuration:

- 200 isolation trees
- `RANDOM_STATE = 42`
- Raw score negated (larger = more anomalous)
- Converted to percentile rank so the threshold can move without retraining

Thresholds:

- **P90 (Top 10%):** 3,116 reviewers flagged → +2 points in score
- **P97 (Top 3%):** 935 extremely unusual → prioritized for human review

### Module 6 — TF-IDF + Logistic Regression Classifier

- Training sample: 20,000 dictionary-matched reviews
- Split: 80/20 stratified
- Vectorizer fit on training fold only (prevents leakage)
- Features: 15,000, 1–2 grams, min_df = 3, max_df = 0.90
- Classifier: LogisticRegression with `class_weight='balanced'`, `C=1.0`
- **Training accuracy:** 0.9222
- **Test accuracy:** 0.8622
- Macro-F1 in the 0.65–0.75 band

### Stage 8 — Score Fusion

A fully **additive, transparent** score combining all module outputs. Every component maps to a checkable signal.

## Scoring Formula

```
forensic_signal_score = evidence_rating              (1–2)
                      + evidence_complaint           (0–3)
                      + evidence_image               (0–1)
                      + evidence_unverified          (0–1)
                      + evidence_rating_deviation    (0–2)
                      + evidence_activity            (0–2)
                      + evidence_negative_behavior   (0–2)
                      + evidence_text_repetition     (0–2)
                      + evidence_temporal            (0–2)
                      + evidence_network             (0–1)
                      + evidence_anomaly             (0–2)
                      + evidence_image_reuse         (0–2)
```

### Priority Bands

| Band                          | Score Range | Cases    | % of Corpus |
|-------------------------------|-------------|----------|-------------|
| Routine review                | ≤ 5         | 37,750   | 62.9%       |
| Contextual examination        | 6 – 9       | 20,750   | 34.6%       |
| High-priority examination     | > 9         | 1,650    | 2.7%        |

The additive design means any score can be **decomposed into its named components**, which is exactly what the exported `evidence_matrix.csv` and `priority_case_narratives.csv` files carry.

## Reproducibility

Every stochastic component reads the same seed (`RANDOM_STATE = 42`):

- The streaming sampler
- The train/test split
- The KMeans initializations
- The 200 IsolationForest trees

The ingestion stage is also **resumable**: it records its byte offset inside the remote 22 GB stream and continues from that offset after a dropped connection (with exponential backoff: 5 → 10 → 20 → 60 seconds, up to 30 retries).

Eleven CSV exports carry every intermediate table out of the notebook, so the chain from raw review → triage band can be audited offline.

## Limitations

1. **Weak supervision.** Classifier metrics measure agreement with the dictionary, not ground truth. A human-annotated validation set is the honest fix.
2. **Single category.** The run covers Electronics only; vocabulary may not transfer to Books or Clothing.
3. **Monthly granularity.** The burst detector treats months independently; intra-month seasonal patterns are invisible.
4. **Image metadata.** Only perceptual hashing is used; EXIF / source metadata is not parsed.
5. **VADER ceiling.** Lexicon-based sentiment misses sarcasm and mixed sentiment by design.

---

## Future Work

- Replace VADER with a fine-tuned DistilBERT sentiment model to lift the sarcasm ceiling.
- Replace LDA/NMF with BERTopic for sharper novel-theme discovery.
- Build a human-annotated validation set to convert weak-supervision metrics into honest ones.
- Add EXIF / metadata inspection to the image pipeline.
- Conduct a threshold sensitivity study mapping queue size to band boundaries.
- Wrap the pipeline as a streaming service that pushes high-priority cases to an operations channel in real time.
